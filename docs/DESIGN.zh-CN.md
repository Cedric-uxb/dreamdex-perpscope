# PerpScope 中文设计说明

## 目标用户

需要在较短时间内验证 dreamDEX 永续 API、SDK、文档和测试网状态的赏金参与者与开发者。

## 核心痛点

人工复制终端输出容易遗漏链 ID、区块高度、市场地址和时间信息；单次异常也容易被误判为 Bug。反馈缺少这些证据时，主办方无法复现，也不会支付奖励。

## 最小方案

PerpScope 只做三件事：

1. 通过官方 Somnia Markets SDK 读取全部活跃永续市场。
2. 用确定性规则检查公开元数据、链上实时价格和订单簿。
3. 输出带时间戳的 JSON、Markdown 和待复验草稿。

## 为什么不使用 AI

本阶段的判断规则是链 ID、地址格式、数值网格和盘口关系，确定性代码比大模型更容易复现、审计和让主办方接受。若后续需要对大量日志归类，可以增加离线辅助分析，但 AI 不参与事实判定。

## 证据分级

- `major`：错误链、无效关键地址、无效市场网格、无法获得链上实时价格、交叉盘口。
- `normal`：通过确定性规则确认、但影响低于 `major` 的可复现问题。
- `inconclusive`：单市场探针失败等无法完成判断的读取结果，不作为问题提交。
- 指标：索引行价格差异、空盘口和单边盘口，只用于后续对比，不作为问题提交。

只有 `major` 和 `normal` 会生成反馈草稿。所有草稿至少复现两次后才能进入公开 `feedback/` 目录。SDK 市场发现不完整时整次扫描失败，避免把部分结果包装成完整证据。

## 安全设计

- SDK 以无账户模式初始化。
- 代码中不存在私钥、签名或交易广播接口。
- 输出不包含钱包信息。
- 单市场失败被隔离，避免丢失整次扫描证据。
- SDK 返回部分市场时停止扫描，避免遗漏被误认为市场不存在。
- 安全漏洞走私下披露，不进入自动报告流程。

## 验证标准

- `npm run check` 全部通过。
- 覆盖率行、函数、分支均不低于 80%。
- `npm run scan` 能读取 chain `50383` 并完成全部活跃市场扫描。
- 结果同时包含 JSON 和 Markdown。
- 单个市场失败不会终止其他市场扫描。

## 暂不实现

- 自动下单和交易机器人。
- 私钥、助记词或钱包连接。
- 数据库与历史图表。
- 多链支持。
- 前端页面。

这些功能会扩大风险和工期，但不会直接提升当前反馈赛道的可复现性。
